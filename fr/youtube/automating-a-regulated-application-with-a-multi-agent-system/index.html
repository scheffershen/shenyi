Automatiser une application réglementée avec un système multi-agents

Aussi en: English · 中文

Regarder sur YouTube ↗Toutes les vidéos

Une application réglementée coûte ce qu'elle coûte à cause des postes, pas de la frappe : sept étapes, autant de passages de relais, une documentation écrite en dernier de mémoire, et un audit qui doit reconstituer qui a vérifié, qui a décidé et quelle était la preuve.

Ce tutoriel montre comment donner chaque poste à un agent et garder une personne à chaque porte. Dix agents Claude Code, trois skills et un script de workflow spécifient, construisent, testent, vérifient, documentent et livrent une petite API Symfony à partir d'un document d'exigences, puis la maintiennent depuis ses logs et sa boîte de demandes. L'orchestrateur n'écrit jamais de code. Le testeur ne lit jamais le diff. Le vérificateur repart de zéro. Le tag, le merge et le push restent les vôtres.

Quatre chapitres : le workflow type d'une application réglementée (trois flux, sept étapes), la démo TicketFlow (les flux de build, de maintenance et de release sur des schémas d'un écran), les concepts fondamentaux (ce qu'est un skill, un agent et un workflow dans Claude Code), et comment construire vos propres skills et agents à partir de votre propre processus.

Ce qu'une session toute neuve a fait sur la démo avec rien d'autre que /improve, le 15 octobre 2026 : deux tours, trois bugs corrigés, deux demandes de fonctionnalité livrées, huit décisions posées et répondues, chaque élément validé à sa première vérification ; le premier tour a pris 27 minutes, le deuxième 9, la release 10. Les chiffres sont dans le dépôt du tutoriel.
