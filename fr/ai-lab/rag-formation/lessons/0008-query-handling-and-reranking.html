1 · The skill

Pick one of q24, q46, q52, or q63 and write a single hypothesis about query normalization or reranking that could fix it.

  • Query normalization: Turn one user question into several searchable forms — the raw question itself, any document IDs buried in it, acronyms spelled out, or terms translated.
  • Reranking: Retrieval gives you a rough first pass; reranking reorders those candidates with stronger signals — an exact identifier match, metadata, a cross-encoder.
  • Deduplication: Collapse repeated chunks from the same document, so your evidence budget goes toward independent support, not the same point twice.

Primary reading: Elasticsearch — Learning to Rank

查询归一化，是把用户的一句话变成好几种能检索的形式：原话、从里面抠出来的文档编号、还原后的缩写、翻译过的说法。重排序，是把检索给的粗略候选结果，用更硬的信号——精确编号命中、元数据、交叉编码器——重新排一遍序。去重也不能少：把同一篇文档里重复的片段合并掉，别让证据预算被同一句话占掉好几个名额。

2 · Run the evidence loop

cd demo
python3 eval.py run --mode retrieval --workspace meridian_demo --category reference_lookup --tag lesson-08-baseline

Write down what source you expected to see, whether the baseline actually surfaced it, the one query variant you tried, and how that same metric moved afterward.

Cranking up top-k just buries a retrieval failure under more noise — it doesn’t tell you what actually went wrong.

把预期命中的来源、基线到底有没有命中、你改的那一种查询写法，还有改动后同一个指标的变化，统统记下来。把 top-k 调大只是让检索失败埋进更多噪声里，说明不了问题出在哪——更不能拿一次实验的结果，就断定整个系统已经靠谱了。

Mission connection

The baseline already tells the story: retrieval union is high, but multi-hop answers are still weak. A tightly controlled query experiment can target that exact failure mode — no need to touch the rest of the pipeline.

基线数据已经把话说清楚了：检索并集命中率不低，可多跳问题的答案准确率还是上不去。做一次受控的查询实验，就能精准打到这个失败点，不用把整条流水线都动一遍。
